Methodology

How the legacy runs were measured

01 — Contract
L1 produces a Task Contract with explicit acceptance criteria before any code is written. The same contract was used to verify both the QB run and the raw baseline; because QB wrote it, the comparison can favour QB.
02 — Execution
QB runs the full 5-layer pipeline. Baseline sends the raw task description directly to claude --print with no contract, no context, no repair loop. Same underlying model in both cases.
03 — Verdict
L4 judges both diffs against the same contract — running the test suite, checking diff scope, scanning for AC keywords, then asking an independent local LLM to judge each AC. Pass = all criteria met.
ZERO API KEYS — HOW
L1 Intent
DeepSeek-R1:7b via Ollama on localhost:11434. Produces the task contract from the raw request.
L3 Agent
Claude Code CLI subscription — claude --print. No per-call charge, no Anthropic API key.
L4 Verify
Same DeepSeek-R1:7b instance, separate context. Independent judgment — never sees the original briefing.
Known limitations

What we know is imperfect

L1 contract accuracy ceiling
DeepSeek-R1:7b occasionally produces incorrect acceptance criteria — a confidently-wrong spec that the agent then implements correctly. T-002 AC-2 wrote "1000ms → '1m'" when 1000ms = 1s. The entire pipeline then validates the wrong behavior.
L4 7B verdict inconsistency
The same diff can receive different verdicts across L4 calls — a 7B model at the judgment boundary. Manifested in T-001 (fail on attempt 1, same code passes on attempt 2). A model router or deterministic post-processing step is the mitigation.
Single-repo legacy record
All 6 legacy tasks test the same JavaScript repo. The frozen development set now spans 5 repositories, all JavaScript; other languages are not yet covered.
Scope drift on repair
T-004 repair attempt 2 modified src/stt.js in addition to the intended src/llm.js. Scope enforcement is not yet applied on repair re-executions. Tracked as a known issue.
Progress tracker · live

What's shipped, what's next

L1 Intent Compiler — LIVE
DSA ambiguity pre-filter (regex, 0ms) + DeepSeek-R1:7b via Ollama → TaskContract. No API key. Validated on 6 fixtures including full vague→clarify→compile loop.
L2 Context Engine — LIVE
Symbol extraction (ESM + CJS), import graph 2 levels deep, test finder, framework/arch detection, git activity. Optional LLM pass ranks files and writes agent brief. Processes 24-file repo in ~500ms DSA, ~40s with LLM.
L3 Agent Orchestrator — LIVE
Structured 140+ line Agent Briefing (0ms DSA). Invokes claude --print and captures the resulting git diff as a structured Changeset.
L4 Verification Engine — LIVE
Test runner (jest/vitest/mocha/node:test), diff scope check, AC keyword scan, independent per-AC LLM judgment. Repair hints generated on failure. Zero API key.
L5 Memory — LIVE
Per-repo JSONL store at ~/.quarterback/memory/. Jaccard-similarity scorer (pure DSA, 0ms). File hints, repair recall, prior contract retrieval. Active by run 3 — src/llm.js recalled at sim=1.00.
Repair loop — LIVE
L4 failures generate structured repair hints → fed back to L3 for automatic re-execution. Max retries configurable (1–10).
Evaluation harness — BUILT
External grader with hidden test suites, equal agent-time budgets per arm, pinned images and immutable, hash-checked experiment records (review findings QB-27 to QB-29, accepted). 30 development tasks across 5 repositories frozen.
Next: controlled evaluation
A capped development pilot on a Linux host with enough memory for the sandbox (about 11 GiB free per run), then an independently authored and reviewed holdout set. No performance results until then.
