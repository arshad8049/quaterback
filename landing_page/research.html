Methodology

How we measure

01 — Contract
L1 produces a Task Contract with explicit acceptance criteria before any code is written. The same contract is used to verify both the QB run and the raw baseline — making comparisons fair.
02 — Execution
QB runs the full 5-layer pipeline. Baseline sends the raw task description directly to claude --print with no contract, no context, no repair loop. Same underlying model in both cases.
03 — Verdict
L4 judges both diffs against the same contract — running the test suite, checking diff scope, scanning for AC keywords, then asking an independent local LLM to judge each AC. Pass = all criteria met.
ZERO API KEYS — HOW
L1 Intent
DeepSeek-R1:7b via Ollama on localhost:11434. Produces the task contract from the raw request.
L3 Agent
Claude Code CLI subscription — claude --print. No per-call charge, no Anthropic API key.
L4 Verify
Same DeepSeek-R1:7b instance, separate context. Independent judgment — never sees the original briefing.
Research angle

Why this qualifies as research

The Quarterback benchmark produces the kind of controlled, reproducible comparison that software engineering research requires. Three claims are testable with the data we have now.

H1
A structured task contract improves agent pass rate over unstructured prompts
Claim: same coding agent, with QB's structured contract + context package, passes tasks at a higher rate than when given the raw description. Evidence: QB 67% vs baseline 33% (+34pp) on 6 curated tasks. Confound controlled for: same L4 contract verifies both sides.
H2
An automated repair loop recovers failures without human intervention
Claim: L4 repair hints fed back to L3 recover failures that the agent could not resolve on first attempt. Evidence: 2/2 recovery rate on T-001 and T-004. Both tasks failed on attempt 1 and passed on attempt 2 with structured repair hints. Baseline failed T-004 entirely — no repair mechanism.
H3
Formal acceptance criteria surface edge cases that raw prompting misses
Claim: the QB contract forces explicit ACs that an agent given a raw description would not implement. Evidence: T-002 — QB contract included ACs for invalid input, negative values, and hours formatting. Baseline implementation passed basic behavior but failed 3/6 ACs. The edge cases were specified in the contract, not discovered post-hoc.
Scope caveat: 6 tasks on one repo is a proof-of-concept dataset. The hypotheses are now falsifiable — the next step is scale (50–100 tasks, 3–5 repos) and independent replication. The beta cohort is the instrument for that.
Known limitations

What we know is imperfect

L1 contract accuracy ceiling
DeepSeek-R1:7b occasionally produces incorrect acceptance criteria — a confidently-wrong spec that the agent then implements correctly. T-002 AC-2 wrote "1000ms → '1m'" when 1000ms = 1s. The entire pipeline then validates the wrong behavior.
L4 7B verdict inconsistency
The same diff can receive different verdicts across L4 calls — a 7B model at the judgment boundary. Manifested in T-001 (fail on attempt 1, same code passes on attempt 2). A model router or deterministic post-processing step is the mitigation.
Single-repo benchmark
All 6 tasks test the same JavaScript repo. Results on Python, Go, TypeScript, or larger codebases are unknown. The architecture is language-agnostic — the context engine has Go/Python detection — but the benchmark does not yet cover them.
Scope drift on repair
T-004 repair attempt 2 modified src/stt.js in addition to the intended src/llm.js. Scope enforcement is not yet applied on repair re-executions. Tracked as a known issue.

L3 Agent Orchestrator — LIVE
Structured 140+ line Agent Briefing (0ms DSA). Invokes claude --print and captures the resulting git diff as a structured Changeset.
L4 Verification Engine — LIVE
Test runner (jest/vitest/mocha/node:test), diff scope check, AC keyword scan, independent per-AC LLM judgment. Repair hints generated on failure. Zero API key.
L5 Memory — LIVE
Per-repo JSONL store at ~/.quarterback/memory/. Jaccard-similarity scorer (pure DSA, 0ms). File hints, repair recall, prior contract retrieval. Active by run 3 — src/llm.js recalled at sim=1.00.
Repair loop — LIVE
L4 failures generate structured repair hints → fed back to L3 for automatic re-execution. Max retries configurable. Recovered 2/2 failed tasks in benchmark. No human intervention required.
