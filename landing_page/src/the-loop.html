How Quarterback works

It wraps the coding agent you already use

Today you hand a task to a coding agent, read what it did, test it, ask for fixes and check again. Quarterback does the checking and fixing rounds, then hands back a proposed change and its evidence for you to approve.

01
Understands the request
Before any code is written, Quarterback turns your request into a short list of requirements and checks. A vague request gets a clarifying question instead of a guess. You review and approve the list. This step runs on your machine with a local model: no API key, no cloud, no per-call cost.
02
Finds the relevant code
It reads your repository to find the files, functions and tests the task touches, so the coding agent starts with the right context instead of searching blind.
03
Runs the agent safely
Claude Code does the work inside an isolated sandbox. It cannot change your files, and it cannot reach the internet except its own service. Quarterback records exactly what changed. Support for other agents is planned.
04
Checks the result
The change is checked against the requirements you approved: first by running your tests and the approved checks, then by a separate reviewer model for what tests cannot answer.
05
Asks for fixes
If a check fails, the agent gets a specific instruction to fix it. Quarterback stops instead of looping when a fix makes no progress.
06
Remembers what worked
Fixes that led to an approved result are remembered and suggested for similar tasks later. Suggestions that never led to a pass are labelled as unproven.
