The runtime

A control loop around the agent you already use

Assign, observe, inspect, correct, test, inspect again, approve. You run that loop by hand today. Quarterback runs the inspect, test and repair part, and hands back a proposed patch with its evidence for you to approve.

01
Intent compiler
A deterministic ambiguity filter runs first — a regex rule engine that intercepts vague patterns at 0ms, before a model is ever called. When the request is clear, a local LLM (DeepSeek-R1 via Ollama) produces a structured task contract: goal, required behavior, constraints, acceptance criteria and a verification plan, which you review and approve. This step runs locally: no API key, no cloud, no per-call cost.
02
Context engine
The contract is grounded in the actual codebase. A deterministic pass extracts exported symbols, traces import graphs two levels deep, identifies test files for affected areas, detects framework and architecture patterns, and surfaces git activity on changed files. An LLM pass then ranks the top files and writes an agent brief — or is skipped entirely for a fast, fully offline run.
03
Execution and observability
The approved contract goes to Claude Code, which runs in an isolated Docker sandbox whose only network route is to its own API. Quarterback captures exactly what changed. Adapters for other agents are on the roadmap.
04
Independent verification
The implementation is checked against the original contract — by a different model, with different context and a different strategy. Deterministic evidence first, judgment second.
05
Automatic repair
A failed criterion becomes a precise repair package and goes straight back to the agent. Quarterback stops instead of retrying when a repair makes no progress.
06
Memory
Repairs that led to an approved pass are kept as project memory and suggested for similar future tasks; suggestions that never led to a pass are labelled as unproven.
